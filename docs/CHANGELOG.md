2026-10-26 · 变化（Transform）
------------------------------------------------------------------------
【背景】
  变化是杀戮尖塔原语境中的"随机变化"：删除一张牌，加入一张随机卡牌。
  当前项目尚无变化代码；事件节点本身也仍是占位。

【已确定】
1. 变化是随机行为，结果随机产生，不是由玩家指定目标牌。
2. 随机数来源：事件流 run.rng.events（EVENTS 域）。
   不借用 shuffle / enemyAi / rewards / map / effects，避免串流。
3. 实现方式：不抽共享函数、不建 deckops 模块。
   每个事件在自己的实现内部写一遍"删除指定卡 + 加入随机卡"。
4. 合法结果池：allCardFactories()。
   它当前等价于"非基础 / 非事件 / 非诅咒 / 非状态"牌；
   事件内不复制排除名单。
5. 结果排除源牌同名，保证一定发生变化。
6. 新牌放回原下标（原地替换），牌组长度与顺序不变。
7. 源牌不限制：基础牌 / 诅咒 / 状态牌都可以被变化，
   是否开放由各事件自行决定。
8. 仅在局外（节点 / 事件 / 商店）调用；禁止在战斗进行中修改牌组。
9. 重构触发条件（未来满足任一再抽函数）：
   - 出现第 3 个变化事件；
   - 出现非事件来源（商店 / 遗物 / 药水）的变化；
   - 结果池需要按稀有度 / 类型加权。

【待定（尚未敲定，不实现）】
1. 事件层接入方式：是否在 RunCallbacks 中新增 event / chooseDeckCard 回调。
2. 具体事件内容：哪些事件提供变化、文案、触发条件。
3. 是否给 Card 增加 CardCategory（当前用 allCardFactories 已足够）。
4. 是否同时收口"加入卡牌 / 删除卡牌"为同级操作。
5. 自动化测试的文件与用例（等实现方案阶段再定）。

【状态】
  仅决策记录，未开始实现。等事件设计确定后，再写实现方案并交接。

2026-11-03 · GUI DPI 模糊修复（已实施）
------------------------------------------------------------------------
【背景】
  GUI 首版固定 initgraph(1280,720)，进程为 DPI Unaware。150% 缩放下
  Windows 把 1280x720 位图放大到 1920x1080，非整数放大导致字体模糊，
  叠加原本 11~18px 的小字号，观感既模糊又偏小。

【已确定】
1. 进程在 initgraph 前声明 PER_MONITOR_AWARE_V2（旧系统回退 SetProcessDPIAware），
   直接按物理像素渲染，不再交给 Windows 位图放大。
2. 设计坐标系保持 1280x720 不变；绘制、字号、HX 控件一律乘以 g_uiScale。
3. g_uiScale 不写死 1.5：取 min(系统 DPI / 96, 工作区可容纳比例)，夹在 [0.75, 3.0]。
   因此 100% / 125% / 150% / 200% 与不同分辨率屏幕都能自适应，窗口不会超出桌面。
4. 鼠标事件由物理坐标换算回设计坐标；hiEasyX 的 PushMessage 仍收原始物理消息。
5. 字号整体上浮 15%，作为小字偏小的统一补偿，不逐处硬编码改字号。
6. 背景渐变逐物理像素行填充：按设计行绘制会在非整数缩放下漏行，
   表现为上一帧内容穿透成扫描线色块。

【待定】
1. 是否需要为超宽屏/竖屏提供非 16:9 的布局（当前按等比缩放，四周留黑边）。
2. 是否在运行中响应 DPI 变更（拖到另一块不同缩放的显示器）；当前只在启动时计算。

【状态】
  已实施并编译通过（gui.cpp 0 错误、自身 0 警告）。150% 环境实测客户区
  1920x1080、dpi=144；菜单/地图/战斗/牌组弹窗文字清晰，无残影、无溢出，
  出牌与瞄准点击命中正常。其它缩放比例待实机确认。

2026-11-07 · GUI 素材接入与大尺寸布局 v2（已实施）
------------------------------------------------------------------------
【背景】
  首张真实素材到位后实测暴露三个问题：立绘没填满显示框、PNG 透明区显示成黑色、
  卡牌与角色偏小。定位到根因后按 rescources.txt v2 重排布局并接入素材。

【根因（均为实测，不是推测）】
1. 透明变黑：本机 EasyX 26.9.25 的 putimage 不混合 alpha 通道。
   探针实测：8x8 半透明 PNG 贴到白底，透明像素被写成 0x000000（黑）；
   且 7 参 putimage 的拉伸参数不生效（目标是 32x32，实际仍按 8x8 绘制）。
2. 没填满：素材外框 213x144，alpha 内容只有 183x131
   （右侧留白 11.3%、上侧 6.9%），图片尺寸不等于角色实际占位。
3. 偏小：drawEnemyArt 原来有 k = min(1.0f, ...)，把缩放钳死在 1 倍；
   150% DPI 下显示框已是 180 物理像素，图片仍按 120 绘制，只占框的 67%。

【已确定】
1. 素材绘制改走 AlphaBlend：加载时把 IMAGE 缓冲（0xAARRGGBB）转成
   预乘 alpha 的 32bpp DIB 缓存，同时统计 alpha 包围盒；
   绘制时用 AlphaBlend 的源矩形裁掉透明边，并按目标框等比缩放
   （目标 DC 用 COLORONCOLOR，保持像素图最近邻硬边）。
   目标 HDC 用 GetImageHDC()，与已有的 fillAlphaRect 同一套机制，不引入新库。
2. 立绘统一「贴底对齐」；缺图仍回退色块占位，占位框内不再重复敌人名字。
3. 布局按 rescources.txt v2：怪物区 640 / 中央 280 / 玩家 360；
   敌人立绘 200/200/193/140；玩家立绘 320x216；手牌 140x195；
